# Decisions

One entry per harness decision: date, decision, why. Newest first.

- **2026-11-07:** Crash recovery for local runs. `run.json` now carries `pid`/`host`/`heartbeat_at` (refreshed every turn); a run stuck at "running" is orphaned when its heartbeat is stale (default 10 min, `STUDIO_ORPHAN_AFTER_MIN`) or its pid is gone on this host (`runner/liveness.ts`, `npm run runs -- orphans`; heartbeat judged first so pid reuse and pre-liveness runs still get caught). The transcript gained `msg`/`note` events recording every message exactly as the model saw it, plus `history` on `start`, `clipped` on tool events, and a `resume` event, so `resumeRun` (`runner/resume.ts`) rebuilds the conversation verbatim and continues the same run id, workspace, spend and caps; period/day caps get the run's earlier spend added back once so headroom is not double-counted. A crash mid-turn leaves tool calls unanswered: recorded results replay verbatim (clipped ones don't), an unanswered submit replays its recorded verdict, everything else answers "interrupted by a crash; check the current state before retrying" — `ask` tools never fire twice. Refused, never guessed: still-alive runs, finished runs, changed specs, transcripts older than msg-recording, corrupt middles; a torn last line is expected after a crash and dropped. Crash tests SIGKILL a real child process at chosen events (`runner/__fixtures__/crash-run.ts`).
- **2026-11-07:** Engine locked: Godot 4.7 (brew cask). Spike results on macOS arm64: plain `--headless` returns null viewport textures (no rendering, ever); windowed runs capture NONBLANK PNGs via SubViewport; `--write-movie` produces real frame data; `--headless --rendering-method gl_compatibility` does not help. So QA/trailer capture runs the desktop build windowed or in movie mode (xvfb on Linux), and the screenshot contract only requires "no visible window dependency" of the game, not headless. Contracts written accordingly (docs/contracts/): one `qa/` file protocol (control.json polled per frame, ack.json, events.jsonl) instead of stdin/sockets — debuggable, engine-agnostic, no threads; JSON Schemas for state-dump and asset-manifest; build.sh fixed targets; telemetry counts standard events.
- **2026-11-07:** `game_repo` capability (game_clone/game_read/game_write/game_exec): each run clones games/<game> into runs/<id>/workspace/game on branch `agent/<name>`; only the Tech Lead merges into main (single-merger rule). game_exec is argv-array only (no shell), non-zero exit is an error result. Unblocked six specs: tech-lead, gameplay-engineer (one per roster slot, ×2), build-release (uploads staged but gated: no send capability yet), qa-lead, playtester, audio (procedural, committed generators only — license-clean by construction). Runner fix from the historian smoke failure: a reply truncated by max_tokens arrives empty and the model re-sent the same giant output until nudges ran out ($0.22 wasted); the nudge now names the truncation and demands small turns, plus a regression test. All 18 specs validate; 50 tests green; historian smoke passed end-to-end ($0.18, timeline + narrative written from studio tools).
- **2026-11-07:** Five more agent specs need no new capabilities, so they ship now: level-content-designer (design), marketing-lead + community-outreach (marketing), finance-compliance + studio-historian (ops), all local on glm-5.3, budgets $3–5/day. Conventions: long-form deliverables (content JSON, store copy, drafts, checklists, timeline) are files in the run workspace and the output_schema returns only the manifest plus numbers copied from tool output, so hand-offs and evals stay checkable; community-outreach is drafts-only because a gated send capability doesn't exist yet. studio_ledger gained `ledger_recent` (counts + newest-first entries, reads tools/ledger) so the Historian and Studio Head can read history, not just write it.
- **2026-11-07:** Studio window (`window/`, lifted from the Fabric web app) + chat with the Studio Head. The UI keeps Fabric's HTTP contract (`window/packages/contracts`, zod); `window/server/` is a thin adapter that serves it from `runs/` and `agents/`, so the UI needed almost no changes. Chat uses Fabric's durable-session protocol: an append-only event log per session (`runs/chat/<id>/events.jsonl`) followed over SSE. Each human message runs one `studio-head` turn through the local runner (new `history` + `onEvent` options), so chat gets the same budget, kill switch and spend ledger as every other run; conversation memory is the log, passed back as history. Every human chat message from the event start (`STUDIO_EVENT_START`, default Sat 2026-11-07 21:00Z = 1 PM PT) is appended to the studio ledger as an intervention, counted conservatively (a pure status question counts too; no classifier). The adapter only allows requests from localhost and the Electron app (it can spend money, so a visited web page must not reach it). `studio_status` capability (read-only: runs, run output, spend, roster) lets the Studio Head answer from evidence. Not yet: the Studio Head cannot start or stop agents; the Weave inbox is empty until approvals exist.
- **2026-11-07:** Studio ledger (`tools/ledger`, capability `studio_ledger`): append-only `runs/ledger.jsonl` with decisions (`log_decision`, attributed to agent + run) and human interventions (`npm run ledger -- intervention "<action>" "<reason>"`). Local backend until the Naïve App MCP server exists; agents call the capability, so the swap needs no spec change.
- **2026-11-07:** Greenlight pipeline: Market Analyst → Player Voice Analyst → Game Director pitches (owner chosen over a new Pitch Writer slot) → Feasibility Critic → revision round(s) → Greenlight Chair pick (`agents/greenlight-chair`; moved out of Studio Head, which another session rebuilt as the operator-facing chat coordinator). Hand-offs are task files built in code (`tools/greenlight/handoff.ts`); `scripts/greenlight-loop.ts` runs pitch/critique/revise up to 2 rounds until 2 pitches survive. The Critic judges sub-scores, hours, and attacks; `tools/greenlight/feasibility.ts` computes the verdict (blocker or score < 0.4 → veto; majors, score < 0.65, must > 10h, or > 160 animation frames → cuts). The Director's must list is budgeted at 10h with its own estimates; it underestimates ~40% vs the Critic (open item).
- **2026-11-07:** Steam reviews come from public Steam Community review pages (cursor paging, ~1 req/s, 7-day cache): the old `appreviews` JSON endpoint now redirects to the store home. Mention rates are counted in code; quotes are checked verbatim (elisions with "..." allowed).
- **2026-11-07:** Gap map, final method: spherical k-means (600) over centered embeddings of all ~117k real releases (tags + genres + description, no names), each cluster scored like a catalog tag over the same window, plus indie share (filter ~0.4) to skip AAA niches, game kNN edges (5) and region adjacency (5). Rejected after testing: novelty of points mixed between two hits (always lands next to a generic game) and fixed-size neighborhoods ("sparse" = incoherent). Names were dropped from the embedding text after title words created false neighbors.
- **2026-11-06:** Naïve's proxy rounds bounded numbers (`minimum`/`maximum` in a tool schema) to integers; the runner strips bounds from model-facing schemas and validates with zod. The runner also has a loop guard (warn at 3 identical failing calls, stop at 5) and retries transient network errors.
- **2026-11-06:** Greenlight gap map (`tools/gapmap`): OpenAI `text-embedding-3-small` (256 dims) over the ~56.6k real games with 10+ reviews; candidates are mixes of two related successful games; score = novelty percentile × adjacent-demand percentile (novelty alone favors empty space nobody wants). Node with typed arrays and worker threads (no numpy); UMAP via `umap-js` with precomputed kNN. The Market Analyst browses regions and probes each gap's description; the eval re-probes to check the copied numbers.
- **2026-11-06:** Market Analyst outputs gaps (tag-defined segments), not pitches. It copies demand/supply stats from `catalog_query niche` and judges feasibility and marketability (0–1); `tools/greenlight/score.ts` computes the plan's score. `niche` percentiles rank against the default `pairs` set so any tag set is scorable. The eval re-runs every query to check copied numbers, comparables, and that cited URLs appeared in the run.
- **2026-11-06:** Local runner (`runner/run.ts`): Anthropic-Messages tool loop; providers are the Naïve proxy (cost from `proxy.call(id).billed_micro_usd`; a missing cost fails the call rather than guessing), OpenAI-compatible endpoints (cost from spec price), and a scripted fake for tests. Structured output via a `submit_result` tool validated with the spec's zod schema; rejections go back to the model. Spend caps: per run, per agent period, global daily (`LOCAL_SPEND_CAP_USD`, default $5), pre-flight estimate = most expensive call so far. Proxy calls are org-level, so Naïve's agent budgets don't cover them. Local `web_search` uses the Naïve data catalogue's "Search Google" tool ($0.00015/call).
- **2026-11-06:** Agent spec format: `agents/<name>/spec.ts` (zod-validated `defineAgent`) + `system.md`. Specs grant *capabilities* (`runner/tools/registry.ts`), mapped to local implementations and to Naïve built-in tools; Naïve gets default-deny tool configs. Budgets authored in USD, converted to micro-USD. `toNaiveAgent()` output verified by a create/get/delete round trip on Naïve (only key-order differences). Harness `pi` (the only GA runnable hosted harness).
- **2026-11-06:** Relaxed "all state in Naïve". The event page requires "All teams must use the Naïve SDK to build their company", not Naïve exclusively. So: hand-offs default to the Naïve board and Files; local state is fine for tool data (catalog DB), caches, and logs; local agents (Eng first) may use superfast non-Naïve inference.
- **2026-11-06:** Local runner gets inference through Naïve's proxy (`client.proxy.messages`, Anthropic Messages shape) instead of a separate provider, so local and hosted agents use the same models and billing. Cost is read from the Naïve ledger, since replies carry only token usage.
- **2026-11-06:** Agents are built and tested one at a time, Market Analyst first. Test runs write to gitignored `runs/`, which is wiped before Sat 1 PM so no test output becomes game content.
- **2026-11-06:** Steam catalog is converted once to SQLite (`data/catalog.sqlite`) with Python's stdlib (no extra deps). Agents query it only through `tools/catalog/query.py`, whose fixed queries do the stats in code; the LLM interprets the results.
- **2026-11-06:** Game repos live in `games/` as separate git repos, gitignored here. Commit history then shows what the studio's agents wrote and when.
- **2026-11-06:** Hybrid runner. Hot workers run locally on fast inference during the event; any agent can be cut over to Naïve individually. State lives in Naïve for both.
